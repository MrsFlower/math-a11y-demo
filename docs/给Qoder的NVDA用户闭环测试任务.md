# 给 Qoder 的 NVDA 用户闭环测试任务

更新时间：2026-08-06

## 一、任务目标

这次不是继续开发公式规则，而是验证真实用户闭环：

> 一个使用 NVDA 的视障用户正在 Chrome/Edge 里阅读网页，遇到读屏读不清的公式，能否通过我们的插件把内容送入系统，听到结构化转译结果，并复制带走。

请从安装 NVDA 开始，完整测试。

测试重点不是“后端接口是否返回正确”，而是：

- NVDA 能不能读到插件侧边栏。
- 焦点是否落在合理位置。
- 状态播报是否清楚。
- 选中内容、快捷键、右键、手动粘贴这些入口是否可用。
- 转译结果是否能被 NVDA 顺畅朗读。
- 用户是否能复制结果并带到记事本。
- 如果某一步失败，用户是否知道下一步怎么补救。

## 二、安装 NVDA

### 1. 下载

请从 NVDA 官方网站下载：

```text
https://www.nvaccess.org/download/
```

不要从第三方下载站下载。

### 2. 安装方式

建议正常安装，不要只用便携版。安装时保留默认选项即可。

安装完成后，先确认 NVDA 可以正常朗读桌面、浏览器、记事本。

### 3. 基本操作准备

测试前先熟悉几个 NVDA 操作：

- `Ctrl`：临时停止当前朗读。
- `Insert + N`：打开 NVDA 菜单。
- `Insert + Q`：退出 NVDA。
- `Tab / Shift+Tab`：在网页和插件控件间移动焦点。
- `Enter / Space`：激活按钮、切换单选按钮。
- 方向键：在文本和部分控件里浏览。

如果 `Insert` 不方便，可用小键盘 `Insert` 或 NVDA 设置里的 CapsLock 方案，但测试记录里要写清楚实际使用的 NVDA 键。

## 五、测试总原则

测试时尽量不用鼠标。按“盲人用户优先”的方式操作：

- 能用键盘完成就不用鼠标。
- 如果必须用鼠标，请记录为问题。
- 每一步都注意 NVDA 是否播报了用户需要的信息。
- 不要只看屏幕判断，要根据听到的内容判断。

每个场景都记录：

- 能不能走通。
- 哪一步卡住。
- NVDA 具体读了什么。
- 用户是否知道下一步。
- 是否有不必要的 LaTeX 天书、符号串、英文混杂。

## 六、测试场景 A：手动粘贴闭环

这是最基本的 fallback 闭环，必须先测。

### 步骤

1. 启动 NVDA。
2. 打开浏览器。
3. 打开插件侧边栏。
4. 用 `Tab` 找到“工作模式”。
5. 确认默认选中“转译原文，不解释”。
6. 用 `Tab` 找到“转译风格”。
7. 确认默认选中“结构朗读”。
8. 用 `Tab` 找到“手动粘贴（兜底）”。
9. 按 Enter 展开。
10. 在输入框里粘贴：

```text
∫f(x)e^(−iωx)dx
```

11. 按 Tab 到“开始转译”。
12. 按 Enter。
13. 听 NVDA 是否播报“正在转译”。
14. 等待结果。
15. 检查焦点是否落到“复制转译结果”按钮。
16. 用方向键或 Tab/Shift+Tab 尝试听结果内容。
17. 预期结果应类似：

```text
对 f(x) 乘以 e 的 负 i 欧米伽 x 次方，关于 x 积分
```

18. 按 Enter 复制结果。
19. 打开记事本。
20. 粘贴。
21. 确认 NVDA 能顺畅读出粘贴后的结果。

### 记录重点

- NVDA 是否能读到“结构朗读”这个选项。
- 粘贴输入框是否有清楚名称。
- “正在转译”和“转译完成”是否自动播报。
- 结果是否容易找到。
- 复制后是否有反馈。
- 记事本里读起来是否顺。

## 七、测试场景 B：选中网页内容后送入插件

这是最接近真实阅读的闭环。

### 步骤

1. 打开测试页面。
2. 用 NVDA 浏览到含有：

```text
∫f(x)e^(−iωx)dx
```

的那一行。
3. 尝试用键盘选中这一段文字。
4. 按插件快捷键：

```text
Alt+M
```

5. 观察侧边栏是否打开或获得焦点。
6. 听 NVDA 是否播报“正在转译”。
7. 等待结果。
8. 检查结果是否为结构朗读稿。
9. 复制结果到记事本。

### 记录重点

- NVDA 下用户是否容易选中公式片段。
- `Alt+M` 是否和 NVDA 或浏览器快捷键冲突。
- 按 `Alt+M` 后焦点是否进入侧边栏。
- 如果焦点没有进入，用户是否能用键盘找到侧边栏。
- 结果是否能直接听到。

## 八、测试场景 C：右键菜单送入插件

这个场景可能需要少量鼠标或键盘上下文菜单键，重点看是否可用。

### 步骤

1. 在测试页选中公式或整句。
2. 按键盘上的“应用程序键 / 菜单键”，或 `Shift+F10`。
3. 在右键菜单中找到插件菜单项。
4. 激活。
5. 观察侧边栏是否进入转译流程。
6. 检查结果。

### 记录重点

- 右键菜单项名称是否清楚。
- NVDA 是否读出菜单项。
- 不用鼠标能否完成。
- 如果菜单项太难找，记录为可用性问题。

## 九、测试场景 D：紧凑文本模式

这个场景验证低视力/复制回文档场景。

### 步骤

1. 插件里保持“转译原文，不解释”。
2. 把“转译风格”切到“紧凑文本”。
3. 输入：

```text
∫f(x)e^(−iωx)dx
```

4. 点击“开始转译”。
5. 预期结果类似：

```text
积分 f(x) × e^(-iωx)dx
```

6. 复制到记事本。

### 记录重点

- NVDA 是否能读出“紧凑文本”单选按钮。
- 紧凑结果是否比原公式更可读。
- 读屏是否会把 `e^(-iωx)` 读得过于混乱。

## 十、测试场景 E：理解模式切换

这个场景验证“先转译，再理解”的产品闭环。

### 步骤

1. 在转译模式下完成一次转译。
2. 找到“转去理解模式”按钮。
3. 按 Enter。
4. 检查是否切换到“理解公式，可追问”。
5. 检查是否进入识别/确认流程。
6. 如果输入是视觉公式，观察是否被正确送去 normalize，而不是被当作 LaTeX 天书。
7. 如果能分析，检查是否出现讲解结果和追问入口。

### 记录重点

- “转去理解模式”按钮名称是否清楚。
- 切换后用户是否知道下一步。
- 视觉公式是否还会被误判为 LaTeX。
- 如果分析失败，错误提示是否有补救路径。

## 十一、测试场景 F：历史记录

### 步骤

1. 完成一次转译。
2. 点击“保存到历史”。
3. 展开“历史记录”。
4. 找到刚才的转译记录。
5. 测试：
   - 复制
   - 重新载入
   - 清空历史

### 记录重点

- 历史记录是否能被 NVDA 当作表格/列表读清楚。
- 类型“转译/理解”是否能区分。
- 按钮名称是否具体。
- 清空历史是否有确认。

## 十三、验收标准

这次测试完成的标准不是“没有 bug”，而是必须回答清楚：

1. NVDA 用户能否在不依赖鼠标的情况下完成“粘贴 -> 转译 -> 复制”最小闭环。
2. NVDA 用户能否从网页选中公式并送入插件。
3. 插件侧边栏是否能被 NVDA 稳定读取。
4. 转译结果是否比原视觉公式更可听。
5. `Alt+M` 是否可用，是否冲突。
6. 历史、保存、复制是否可用。
7. 如果不能完成闭环，阻塞点在哪里。

最重要的红线：

```text
∫f(x)e^(−iωx)dx
```

在 NVDA 用户闭环中不能再原样返回，也不能让用户只能听到一串难以理解的符号。
