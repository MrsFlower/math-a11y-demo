# 公式转译结构扫描重构记录

更新时间：2026-08-08

## 背景

真实用户和录屏准备阶段暴露出一个趋势：公式解析失败不只是某个正则没写全，而是 LaTeX 结构本身有嵌套层级。

旧逻辑主要依赖正则，例如：

```python
\\frac\{([^{}]*)\}\{([^{}]*)\}
\\sqrt\{([^{}]*)\}
```

这类规则只能处理一层花括号，遇到下面的公式就会失效或残留：

```latex
\frac{1}{\frac{x+1}{x+2}}
\sqrt{\frac{x+1}{x+2}}
```

## 本次改动

在 `app/transcriber.py` 中新增 `_normalize_latex_structures()`，作为 `transcribe_by_rules()` 的前置阶段。

当前支持：

- `\frac{...}{...}`
- `\dfrac{...}{...}`
- `\tfrac{...}{...}`
- `\sqrt{...}`
- `\sqrt[n]{...}`
- `\int_{...}^{...}` / `\int^{...}_{...}`
- `\sum_{...}^{...}` / `\sum^{...}_{...}`
- `\prod_{...}^{...}` / `\prod^{...}_{...}`
- `x_{...}`、`x^{...}` 的花括号复杂上下标

同时在 token 规则中兜底处理：

- 裸 `\sum` -> `求和`
- 裸 `\prod` -> `连乘`

实现方式：

- 按字符扫描命令。
- 用配对括号读取 `{...}` 或 `[...]`。
- 对分子、分母、根号内容递归处理。
- 输出仍沿用旧规则能理解的中间形态：
  - `\frac{a}{b}` -> `(a)/(b)`
  - `\sqrt{x}` -> `√(x)`
  - `\sqrt[3]{x}` -> `3次√(x)`
  - `\int_a^b` -> `积分(从a到b)`
  - `\sum_{i=1}^{n}` -> `求和(从i=1到n)`
  - `\prod_{k=1}^{m}` -> `连乘(从k=1到m)`
  - `x_{\frac{1}{2}}` -> `x 下标 (1)/(2)`
  - `x^{\frac{1}{2}}` -> `x 的 (1)/(2) 次方`

这样后面的 Unicode 转译、结构朗读、残留检测可以继续复用。

## 后续扩展原则

不要再优先往 `_LATEX_RULES` 里堆复杂结构正则。

建议判断标准：

- 如果是没有嵌套的 token 替换，例如 `\sin`、`\pi`、`\leq`，放在 `_LATEX_RULES`。
- 如果需要读配对花括号、上下限、分子分母、根号内容，放进结构扫描阶段。
- 如果需要面向中文朗读表达结构，例如“分母分之”“根号下”“从 A 到 B 积分”，放进 `to_spoken_structured()`。

下一批适合进入结构扫描的对象：

- 分段函数、矩阵、cases 环境。
