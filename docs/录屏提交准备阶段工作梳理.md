## 二、提交前质量修复（08-08）

### 1. 自带测试页提取只识别 5/10
- **根因**：场景 6/7 的 5 个纯文本公式（如 `x = (-b ± sqrt(b^2-4ac))/(2a)`）
  不在 KaTeX/MathJax DOM 里，原提取管线不覆盖。
- **修复**：content.js 新增第 7 优先级捕获源——正文 `p/li` 里按数学标记正则
  （sqrt/log_/^/下标/±∫∑√∞ 等）捕获纯文本公式。
- **验证**：CDP 实测测试页提取 10/10；两份测试页说明文档同步改预期 10 条；
  Alt+M 残留文案改为 Ctrl+Shift+M。

### 2. 求根公式转译符号残留
- **现象**：`x = (-b ± sqrt(b^2-4ac))/(2a)` 转译后仍残留 ±/√/括号结构，
  读屏用户听不出分数层级。
- **修复**：transcriber.py 新增**结构朗读管线**（spoken_structured）——
  括号配对扫描读分式「分母 分之，括号 分子 括号」（支持嵌套）、递归读根号
  「根号 X」、Unicode 上标读「的平方/的立方/的 N 次方」、±读「加减」、
  二元减号读「减」vs 一元负号读「负」。
- **结果**：「x 等于 2a 分之，括号 负 b 加减 根号 b 的平方 减 4ac 括号」。
- **踩坑**：Python 正则 `\w` 含中文，导致 `(?<![\w])-` 对「平方-4ac」永不触发，
  改用 `(?<![A-Za-z0-9])`；后续再区分二元/一元语境。
- **回归**：用例 34→35 条（新增 plain_quadratic_spoken_structured），35/35 通过。

## 四、AI Studio 试卷页修复链（08-08 晚，用户实测报「页面不能用」）

复现场景：用户在 AI Studio 粘贴高等数学期末考试试卷（51 个 KaTeX 公式），
插件提取/转译全部失败。

### 根因
KaTeX 渲染公式含隐藏的 `.katex-mathml` 读屏层（clip 定位隐藏而非
display:none）。选中公式时该层逐字泄入选区，产出双层乱码
（如「𝑥\n→\n0\nx→0」），后端规则全部失配；innerText 同样被污染，
连带上下文（contextOf）也带乱码。

### 修复（前端 + 后端双侧）
**前端（插件 0.6.5 → 0.6.6）**：
1. background.js `readSelection`：克隆选区后把 .katex/mjx-container 容器
   替换为其 LaTeX 源码（annotation/script/math[alttext]），包成 `$…$`；
   块级元素后插换行占位，选项 A/B/C/D 不再连成一串。
2. content.js `contextOf`：克隆节点后剥离读屏层/源码标签再取文本。
3. content.js 提取上限 MAX 30 → 60（该试卷一页 51 个公式，30 会截断半张卷子）。

**后端（transcriber.py）**：
4. LaTeX 函数名规则（\sin/\ln 等 20 个，长名在前防前缀吃）——不补这条，
   残留反斜杠会每次都静默落 LLM 兜底烧额度。
5. `_latex_lim` 重写——原代码引用不存在的 group(2)，大极限公式直接 HTTP 500。
6. 二元减号两侧允许空格（LaTeX 风格 `x - \sin x` 读「x 减 sinx」）。

**产物 2**：`dist/math_a11y_assistant_aa67882a-0.1.0-py3-none-any.whl`
（2a3c24db 不含 4/5/6 三项），用户已上传，云端复验通过。

### 验证记录（CDP 实测 + 云端复验）
- 选区读取：输出干净 `$LaTeX$`，无双层乱码，选项分行 ✅
- 试卷页提取：55 条（MAX=60 生效，不再截断）✅
- 上下文：读屏层剥离后无乱码 ✅
- 大极限公式朗读：「lim(x→0)x 的平方 ln(1 加 x) 分之，括号 x 减 sinx 括号」✅
